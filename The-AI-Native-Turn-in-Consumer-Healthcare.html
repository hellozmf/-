执行摘要

三句话先讲清楚

黄院问的三件事——想象中的样子、现状的差距、年底必须干成的事——本质上是一个 Vision–Gap–Action 的战略叙事。这一节先用三句话给出答案,后面八章是论证与展开。

关于"想象中的样子"

我们的终局不是单一图景,而是分场景定义。大 B 团检:成为 HR SaaS 和保险 agent 优先调用的能力提供方。小 B 团检:用 AI 武装销售团队,让我们的方案在售前比对手更专业、更差异化、更高效。检后转化(含医美口腔等消费医疗延伸):自有 C 端入口确保高价值环节不被外部 agent 截留,把医美/口腔/慢病等纳入检后健康管理供应链。C 端自费:对外能影响各平台 C 端健管 agent 的决策,对内能在自有场域提供极致的定制化服务和履约。内部医疗质量与门店扩张:用 AI 把总检、影像、超声、漏检质控、导检整合为"标准化扩张包",让新店的报告质量在 day 1 就接近成熟水准,扩张速度不再受限于单一岗位的招聘节奏。

关于"现状与差距"

我们目前在 AI 应用上处在"生成阶段成熟期 + 推理阶段早期"——这个判断主要针对 C 端场景;在 B 端场景下,我们其实还要更早一些。AI 总检、健康管家、AI 导检、加项推荐已经把生成阶段的能力都做出来了。最大的差距不在技术,在组织、流程、入口、服务这四个维度——这四件事都需要被作为独立工作流推进,且每一个都有自己的终局、路径、误区和卡点。

关于"年底必须干成的事"

四场必赢之战:I,三产品融合 + 医技 AI 整合,建成体检系统底座(同时承担 agent native 入口和门店标准化扩张包两个功能);II,加项 API 化,优先服务自家健康管家、HR SaaS、保险 agent;III,启动数据资产化基础工程;IV,B 端双轨建设——大 B 推进 SaaS / 保险 agent 对接,小 B 推进 AI 销售赋能。

"agent 化"在不同场景下意味着完全不同的事情。
大 B 是接入系统的 agent,小 B 是武装我们自己销售的 AI,C 端是影响 agent 决策 + 自己提供极致服务。
01 SEGMENTATION
业务场景分层

先把"消费医疗"拆开:三大场景,五条路径

在讲终局、现状、威胁之前,必须先把业务场景拆清楚。"消费医疗 AI 化"是一个被滥用的概念——它在大 B 团检、小 B 团检、检后转化、C 端自费这四类业务里走法完全不同。其中 B 端要进一步拆为大 B 和小 B 两条路径,因为它们的 agent 化形态本质上不一样。

体检业务的现金流结构是非对称的:B 端团检约 80% 营收,C 端自费约 20%,但检后转化(加项 + 健康管家 + 后续消费医疗,包括医美 / 口腔等)的客单价和毛利率显著更高。我们用三大场景 + 五条路径来组织判断。

这个拆分意味着什么

"agent 化威胁"和"agent 化机会"在不同场景下意味着完全不同的事情:

  • 大 B 团检里,核心是系统接入。HR SaaS 的供应商池、保险公司的组合包,这些"系统级"的入口是核心。值得说明的是:我们可能已经是部分 SaaS / 保险方案的供应商,问题不是"未接入",而是"接入深度是否到 agent 级别、是否拿到优先位置"。
  • 小 B 团检里,核心完全不是系统接入。小 B 客户决策路径短、规模小、对差异化高度敏感。这里 agent 化的真正机会是武装我们自己的销售团队——让 BD 在售前用 AI 快速生成更专业的方案、更精准的需求洞察、更高效的客户响应。这是"AI 销售助手"赛道,不是"AI 进销售对手系统"赛道。
  • 检后转化里,威胁是"用户拿到报告第一时间扔给京东康康或 Apple AI 而不是看我们的健康管家"。机会是:用户检后健康焦虑被激活,这是把医美 / 口腔 / 慢病管理 / 营养等消费医疗品类作为延伸供应链推荐的高转化窗口。医美/口腔不是独立场景,是检后转化的延伸供应链。
  • C 端自费里,"成为京东健康自家 agent 的核心服务节点"只是基础。真正的终局是双层——对外能与各平台 agent 协作并影响其推荐,对内能在自有场域提供极致服务和履约。
  • 内部医疗质量与门店扩张是被前四个场景容易遮蔽、但实际上最先见效、最容易量化、最支撑业务扩张的场景。它的核心是把 AI 用在体检中心内部——总检、影像、超声、漏检质控、导检调度——目的不是直接面向客户,是让我们能用更少的人完成更高质量的体检,并降低门店扩张对单点人才招聘节奏的依赖。这一层的项目我们已经在做,且部分已经跑出可量化的效果。
不存在统一的"消费医疗 AI 化策略"。
大 B 进系统,小 B 给销售装上 AI,检后延伸供应链,C 端在场内做到极致,内部 AI 协同支撑扩张——五件事,五种动作。

这一章是后续所有章节的基线设定。下文每一个判断、每一条威胁路径、每一场必赢之战,都会标明它针对哪个场景 / 路径。

02 FOUNDATION
底层判断 · 三阶段曲线

AI 不是工具升级,是商业逻辑的重写

AI 的发展不是渐进式的能力提升,它会经过三个阶段——生成、推理、代理。我们用一张"在体检业务里具体长什么样"的图来理解这三阶段——而不是抽象描述。

"AI 集成"、"AI native"、"agent native"是三件不同的事——AI 集成是给既有产品加 AI 模块,AI native 是产品架构围绕 AI 重新设计,agent native 是产品的客户从"人"变成"人的 agent"。下面用一张具体场景表把这三阶段讲清楚。

三阶段在 B 端和 C 端走的不一样

需要明确的一点:三阶段曲线在 B 端和 C 端的演进节奏不同,且 B 端内部大 B / 小 B 路径也分化:

  • C 端:落地快但确定性低。大厂在 2025 年密集出牌(下一章详述),但产品形态、商业模式都还在试错。
  • 大 B:推理阶段早期。HR SaaS 集成 AI、保险公司 agent 化采购,这些事在 2024–2025 年已经开始,但走的是稳态 SaaS 集成路径。
  • 小 B:还在生成阶段早期。但 AI 销售赋能在生成阶段就有显著业务价值——这是一个"低阶段、高价值"的特殊场景,不需要等代理阶段,2026 年内就能见效。

对体检业务的含义:C 端的 agent 化我们要警觉但不必恐慌;大 B 的 agent 化要主动跟进;小 B 的 AI 销售赋能要立刻做,因为投入产出比最快。

为什么 2026 是关键节点

  • C 端:大厂入口型 agent(京东 AI 京医、Apple Project Mulberry、腾讯健康管理助手)在 2025 年密集出牌,2026–2027 进入产品形态稳定期。
  • 大 B:HR SaaS 和健康险 agent 的供应商网络在 2026–2027 形成。一旦池子定下来,新进入者和后入升级者的成本都会高得多。
  • 小 B:同行竞争对手中,谁先用 AI 武装销售团队,谁先在小 B 售前环节形成专业度差异。这是一个还没有人显著领先的窗口。

03 VISION
终局图景 · 分场景定义

不做最大的体检中心,做不同场景下能力最深、服务最极致的玩家

黄院问的第一个问题:"特别想象中是什么样子。"——这是终局问题。我们的终局图景按业务场景分别定义,因为四类路径的 agent 化形态完全不同。
QUESTION FROM 黄院
"我们特别想象中是什么样子?"

三年后的世界:用户的健康决策被各种 agent 接管(京东自家、Apple Health Coach、保险公司、企业 HR);企业 HR 的采购决策被 SaaS 智能助手影响;小 B 老板的体检决策仍然由销售关系驱动,但销售背后是不是有 AI 武装,差距会被放大。我们的目标不是去"对抗"这些 agent,也不是去"成为某个 agent 的服务节点"那么被动——而是在每个场景里,把能力做到最深、服务做到最极致。

场景 A · 大 B 团检(系统对接型)

终局图景:成为 HR SaaS 供应商池和保险 agent 组合包中的优先选项,且对接深度达到 agent 级别。

具体来说:北森、Moka、薪人薪事的"员工福利智能助手"在给企业 HR 推荐体检供应商时,我们是默认推荐;平安、众安、水滴这类保险公司的"团险 + 体检 + 健康管理"组合包里,我们是默认的体检合作方。这里的关键不是"是不是供应商",是"对接深度有没有到 agent 级别、有没有拿到优先位置"。结构化的服务质量数据(完成率、员工满意度、复购意向)进入 agent 评分体系,我们排名靠前。

这个终局的关键不是"打动 HR",是"打动 HR 的 agent"——agent 不看销售关系,看的是结构化数据。

场景 B · 小 B 团检(销售赋能型)

终局图景:我们的销售团队是行业里最专业、响应最快、方案最差异化的——背后是 AI 武装。

小 B 客户(中小企业主、行政、HR)的决策路径短、规模小、对差异化敏感。他们买的不只是"体检",是"销售给我看的方案、给我的解释、给我的服务承诺"——这是一个高度"人服务人"的售前场景,在可见的未来里都不会被 agent 接管(因为客户也不想跟 agent 谈)。

但我们的销售背后能不能有 AI 武装,会显著拉开差距。具体形态:

  • 销售拿到客户基本信息后,AI 在 5 分钟内生成针对性的体检方案(基于行业、年龄结构、健康风险画像)。
  • AI 提供"客户行业常见健康风险 + 推荐套餐组合 + 历史成功案例"的售前材料,销售直接拿来用。
  • AI 实时辅助销售应对客户问题(我们的某个项目和对手的区别、合规问题、定价空间)。
  • AI 帮销售做客户跟进的节奏管理(什么时候 follow up、用什么角度切入、过往沟通要点)。

这条路径的好处:2026 年内就能见到业务效果,不依赖代理阶段的到来。是投入产出比最快的一战。

场景 C · 检后转化(含医美 / 口腔等消费医疗延伸)

终局图景:"现场 + 入口"双重在场,把用户检后的健康管理生命周期(包括医美 / 口腔 / 慢病管理)做成一条完整的供应链。

具体来说:用户进入体检中心前,我们的健康管家已经基于他的历史数据预判了加项需求;体检中现场,医生有 AI 辅助系统给出基于实时数据的个性化推荐;体检后报告生成的同时,自家健康管家主动推送解读、复查建议、以及与本次体检发现相关的消费医疗推荐(医美修复、口腔保健、慢病管理订阅等)。

这里的关键判断有两个:

  1. 我们必须自己做 C 端入口产品(健康管家),哪怕用户量做不过外部 agent——只要有自己的入口,就能保住"现场加项 + 报告解读 + 检后延伸"这条高价值链路。
  2. 医美 / 口腔等不再作为独立业务线,而是作为检后健康管理供应链的延伸品类。我们在体检之后已经掌握了用户最完整的健康画像,这时候推荐相关消费医疗的转化率,显著高于第三方触达。这是把"高 LTV 的纯 C 业务"放在"最有信息优势的转化窗口"里推。

场景 D · C 端自费体检(对外影响 + 对内极致)

这是被低估的场景。客单价低于检后转化,营收占比也只有 20%,但它是用户对品牌建立第一印象、形成长期信任的入口。一个 C 端自费用户做完体检后,后续可能产生 5–10 倍单次体检价值的检后转化(医美、口腔、慢病、家人体检等)——所以 C 端自费的终局不能只看体检本身。

真正的终局是双层:

对外:从被动节点 → 主动影响 agent 决策

"成为京东健康自家 agent 的核心服务节点"是基础要求,不是终局。基础之上,真正的能力是:

  • 与各平台 C 端健管 agent 对接——不只是京东自家的,还包括外部 agent(在合规和商业框架允许下)。
  • 能影响这些 agent 的决策——通过结构化的服务质量数据、专业能力背书、用户反馈,让 agent 在做体检推荐时更倾向于我们。这不是"被推荐",是"参与定义推荐标准"。

对内:用户进入我们场域后,提供极致的定制化服务

这是更难、也更值钱的一层。当用户已经决定在我们这里做体检后,他得到的服务质量必须是行业里最极致的——个性化、全面、顺滑、专业、体贴入微。具体包括:

  • 个性化定制方案——不是套餐选择,是基于用户健康画像、家族史、生活方式、风险偏好的真正个性化方案设计。
  • 全面贯穿的连续服务——从决策、预约、到检、检中、报告、解读、随访、健康干预,每一步都有连续记忆,不是断裂的几个产品。
  • 顺滑的体验——少排队、少等待、少重复填表、少切换 App,所有交互一致且简单。
  • 专业且体贴的人工介入——在 AI 协同的基础上,有医生、健康管理师、客户经理的恰到好处的人工服务介入。

这一层是 agent 化时代真正的护城河。因为 agent 可以决定"推荐谁",但用户来了之后能不能得到最好的服务体验,完全在我们手里。一个用户在我们这里得到极致服务,他下一年的 agent 推荐里,我们也会获得更高的权重(通过反馈机制)。

场景 E · 内部医疗质量与门店扩张能力

这是前四个场景之外、但实际上最先见效、数据最扎实的场景。它的关键词不是"客户",是"我们自己"——AI 在体检中心内部支撑医疗质量控制、影像阅片、超声录入、报告总检、漏检防控等一系列原本受医生工时和质量稳定性限制的环节。

终局图景:每开一家新店,报告质量与服务标准在 day 1 就接近成熟水准,而不是等半年到一年让团队"养成";每一份报告,质量上限和下限都由 AI + Eval 体系保障。

具体来说,这个场景的终局有三个特征:

  • 报告质量从依赖个人转为依赖系统。AI 总检承担首检的主要工作量,医生承担关键判断和兜底;漏检质控(尤其是重阳召回、肺结节、动脉瘤等)由 AI 影像辅助系统持续运转,而不是依靠医生轮班自查。
  • 医技岗位从执行型转为判断型。超声录入、影像初筛、一般检查这些重复性工作被 AI 接管,医技人员专注于异常发现、临床判断、患者沟通。岗位数量下降,人均价值上升。
  • 门店扩张可被复制。开新店不再是"复制一个体检中心 + 招齐医生",而是"复制一套标准化的 AI + 人协同流程"——这是跨地域扩张的基础设施。

这个场景对老板而言有一个特殊价值:它是当下就能拿出量化效果的部分。我们已经在这条线上跑出了实绩——AI 总检 AHT 从 3.26 分钟降到 1.94 分钟,首检通过率从 7.8% 升到 49.3%;AI 导检上线后单院预计省 4 个导检岗、10 院共约 40 岗;AI 超声助手 POC 完成、6 月全面部署——这些都是已经在跑或即将上线的项目。配合医技团队推进的 AI 影像辅助阅片、漏检质控等模块,整体上能形成一套较完整的"体检中心 AI 能力组合"。具体数据详见下一章的现状盘点。

C 端自费的终局不只是"成为生态节点"——那是基础。
真正的护城河是"用户进了我们的门之后,得到行业里最极致的定制化服务"。

同业扫描给我们的判断

  1. 方向已经被验证——头部同业都在做主检 AI、健管 agent、个性化推荐、多智能体协作。这不再是"要不要做"的问题,是"用什么差异化竞争"的问题。大方向没有走错。
  2. 我们晚但不晚太多——美年 2024 升级 "All in AI",爱康 2023 推 iKKie——我们从 2024-2025 同步起步,落后大约半年到一年的体量,但还在追赶窗口期。2026 年内是关键追赶年。
  3. 我们的差异化在京东集团协同——美年和爱康都在"自建 AI 能力 + 找供应商合作"两条路径上前进。我们独有的杠杆是京东集团的电商履约、互联网医疗、保险、用药、京医千询大模型、京东 AI 京医等——这些是单纯做体检的同业没有的。这呼应了第 3 章 C 端自费场景"对外影响 agent 决策"的终局判断。
  4. 爱康"输出 AI 能力到第三方"的动作值得关注——这把 AI 从"内部降本工具"变成了"对外授权产品"。直接呼应我们第 4 章流程维度差距里讲的"服务 API 化"和必赢之战 II"加项 API 化"。我们要做的事,行业里已经有人开始做了。
  5. 美年规模优势在数据和场景——2 亿体检人次的历史数据规模是我们短期内难以追平的。这意味着在"数据驱动的精准筛查"这一层,我们应该通过技术深度(京东健康大模型 + agent 架构)而非"数据规模"取胜。

B 端大 B 路径:动作在,标杆未现

B 端 agent 化的玩家更分散,目前没有像 C 端"康康"或"Mulberry"这种公开级别的旗舰产品。几条管道在铺:

  • HR SaaS 集成 AI 福利助手——北森、Moka、薪人薪事在 2024–2025 年加速集成,方向明确。
  • 保险公司"团险+体检+健康管理"组合化——平安、众安、水滴等在做,部分已与体检机构有合作管道。
  • 京东健康自身的 B 端能力——B 端业务也在做 AI 化,但目前还没有公开的 agent 化标杆。

B 端小 B 路径:几乎是空白窗口

这是被忽视的一块。"AI 销售赋能"在通用 SaaS 领域(销售易、纷享销客)已经有产品,但在医疗 / 体检行业的销售场景下,几乎没有专门的玩家在做。

  • 没有现成的对手可以学习,也没有现成的产品可以采购。
  • 但也没有显著落后的对手。这一块是"早做早占住"的空白窗口。
  • 方法论可以从邻近行业借鉴——通用 AI 销售助手(Microsoft Sales Copilot、Salesforce Einstein)的产品形态,结合医疗 / 体检行业的专业知识做垂直化定制。

关键学习:借鉴方法不借鉴产品

  • 从 Apple Project Mulberry 学:AI agent 健康助手的产品哲学(数据整合、对话型交互、AI agent + 人医师视频的混合)。
  • 从京东健康"AI 京医"学:多智能体协同架构(医生、药师、营养师、心理师等分角色)。
  • 从腾讯"健康管理助手"学:不做独立 App、直接嵌入主入口的轻量化路径。
  • 从美年"健康小美"学:主检 AI + 多智能体平台 + 销售智能体的全链路覆盖,但要做到比它更深的产品融合,而不是平铺式叠加。
  • 从爱康"iKKie + 智汇康云"学:从内部 AI 工具到对外能力授权的演进路径——它已经走在前面,印证了我们必赢之战 II "加项 API 化"方向的正确性。
  • 从通用 AI 销售助手学:AI 在售前环节赋能销售的产品形态,迁移到体检小 B 销售场景。
  • 从 Anthropic / OpenAI 的 agent 架构学:多 agent 系统的工程分层(协调器 + 工具层 + 记忆层 + 安全层)。

07 MUST-WIN BATTLES
必赢之战 · 年内四场仗

年底之前必须干成的四件事

黄院问:"如果我们今年在年底之前做,有哪个事情是咱俩必须要干成的?"四场仗的设计依据是:第一,做成了能形成结构性优势,且不会在半年内被对手轻易复制;第二,做不成会让我们在代理阶段被永久边缘化;第三,做这件事必须由我们自己亲手做。

I
MUST-WIN BATTLE I
三产品融合 + 医技 AI 整合 · 建成体检系统底座
2026 Q2–Q4

战役内容。把 AI 总检、健康管家、AI 导检从今天的三个独立产品,重新规划为一个"agent native 体检系统"的三个 sub-agent。三者共享用户状态、共享决策、共享数据资产。同时把影像、超声、重阳质控等已有的医技 AI 模块整合进同一个体系,形成"标准化扩张包"。

主要服务场景:检后转化(高单客价值环节,包含医美/口腔延伸)+ C 端自费的对内极致服务 + 内部质控与门店扩张能力。

为什么必须干成。这是所有后续工作的底座。三个层面都依赖它:对外提供统一 agent 能力依赖产品融合;对内的 C 端极致服务依赖用户状态在产品间无缝流动;新店扩张依赖"标准化 AI 部署包"。三件事都做不到时,我们就只有一堆零散的 AI 产品,业务效果远低于 Demo 效果。

关键里程碑(节奏感,非硬承诺)。

  1. Q2:形成"统一架构"内部共识——把三产品的状态模型、共享数据模型、责任结构梳理清楚,与医技团队对齐"门店标准化部署包"的整合范围。
  2. Q3:在试点中心推进融合 demo,跑通"用户来意 → 套餐推荐 → 体检过程动态调度 → 体检后纵向解读 + 延伸推荐"的端到端链路。
  3. Q4:进入小范围灰度运行,Eval 体系开始常态化,逐步沉淀"新店部署"的初版 SOP。

主要服务场景:检中加项 + 大 B 团检企业级方案 + C 端入口。

IV
MUST-WIN BATTLE IV · B 端双轨建设
大 B 升级对接深度 · 小 B 推进 AI 销售赋能
2026 Q2–Q4

轨道 A · 大 B 对接深度升级

我们大概率已经是部分 HR SaaS 平台和保险公司的供应商。这条轨道的真正动作不是"零到一接入",是"对接深度的升级"——从普通商务关系升级到 agent 级别的数据对接,从被收录升级到优先位置。

具体动作:

  • 盘点现有合作的 HR SaaS / 保险公司,识别哪些已经在 agent 化、深度对接的优先级。
  • 选 2–3 家头部合作伙伴,把现有商务关系升级为 agent 级别的数据 / 服务接口对接。
  • 建设"企业团检服务质量结构化数据"(完成率、员工满意度、HR 复购意向),用于在 agent 评分体系中拿到优势排名。

轨道 B · 小 B 销售 AI 赋能

这是关键路径,也是2026 年内投入产出比最快的一战。具体动作:

  • 建设"销售助手"AI 工具——给 BD 用,不给客户用。核心能力:5 分钟内基于客户信息生成针对性体检方案、生成行业健康风险洞察、生成差异化销售话术、辅助客户跟进。
  • 把内部最佳实践(优秀销售的方案模板、成功案例库、客户应对话术)结构化为 AI 知识库。
  • 选 1–2 个销售大区做试点,跟踪"用 AI 助手的销售 vs 不用的销售"的转化率、客单价、成单周期对比。
  • 形成标准化操作手册和培训体系,在销售团队内推广。

为什么这两轨必须放在同一场战役里。因为它们都属于"B 端战线",资源调度、KPI 设计需要统一管理——但具体动作完全不同。把它们分成两个独立战役会导致资源碎片化,合在一起又会导致一刀切。

关键里程碑(节奏感,非硬承诺)。

  1. Q2:大 B 轨道梳理现有合作伙伴的对接深度现状,识别适合优先升级的目标;小 B 轨道完成销售助手的 MVP 内部验证。
  2. Q3:大 B 轨道与个别合作伙伴探索 agent 级别的对接试点;小 B 销售助手选取试点大区,观察对销售流程和产能的实际影响。
  3. Q4:大 B 轨道沉淀对接经验,形成可复用的方法;小 B 销售助手在试点验证基础上,逐步在更多销售团队中推广,持续打磨工具与流程。

四场仗的关系

  • 战役 I 是底座。没有融合的 agent native 体检系统,后续战役都缺产品基础。
  • 战役 II 是双向接口。它把战役 I 的能力对自家、对 HR SaaS、对保险 agent 暴露——同时服务战役 III 和战役 IV。
  • 战役 III 是长期地基。回报在 2027–2028 才显现,但启动必须在 2026。
  • 战役 IV 双轨。大 B 轨道与战役 II 协同;小 B 轨道相对独立,投入产出比最快,是 2026 年内最容易拿出业务效果的一战。

组织设计建议:跨职能战队

这四场仗的特殊性是:既不是单纯的产品项目,也不是单纯的技术项目,也不是单纯的商业项目。如果按现有组织架构推进,每一场仗都会被各部门的局部利益拉慢。

建议成立跨职能虚拟战队,具备:

  • 跨部门资源调度权——可以从产品、技术、数据、B 端 BD、销售运营、合规各部门拉人。
  • 独立预算——不依赖原有产品线预算审批。
  • 自有 KPI——围绕四场仗的关键里程碑。

这是组织架构的"突击队"模式。这种模式在大组织里推进战略级转型时被反复证明有效,因为它绕过了"每个部门都同意才能动"的瓶颈。
